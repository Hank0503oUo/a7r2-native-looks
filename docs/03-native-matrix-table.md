# 03 原生色彩矩陣表 `0x00030001` 與各槽對應

## 怎麼找到的

原生風格一定有自己的色彩矩陣。在機身 `Backup.bin` 的 19,466 項屬性裡搜尋兩種東西：

- **單位矩陣：** 1.0 可能寫成 256、1024 或 4096。
- **3x3 矩陣：** 連續三列、每列加總約 1024，而且對角線是每列最大值。

這個搜尋工具是 [`tools/find_matrix_tables.py`](../tools/find_matrix_tables.py)，結果如下：

```
0x00030001 size=1536 attr=0x8: identity matrix (2-byte words) at word 566
0x00030001 size=1536 attr=0x8: 18 matrices with rows summing to 1024 at int16 [36, 45, 54, 63, 72, 81, 90, 99, 108, 117, 401, 512, 521, 530, 539, 548, 557, 566]
```

## 格式

| 項目 | 內容 |
|---|---|
| 屬性 | `0x00030001`，1536 bytes，attr `0x8`（寫入時會觸發回呼） |
| 編碼 | 768 個 little-endian int16 |
| 矩陣 | 17 組 3x3，以列為主序，1.0 = 1024，原廠的每列加總為 1024（±1） |
| 位置 | int16 索引 36, 45, 54, 63, 72, 81, 90, 99, 108, 117, 401, 512, 521, 530, 539, 548, 557，分別叫第 0 到第 16 槽 |
| 其他 | 索引 566 是單位矩陣，用途不明，沒有動它 |
| 預設值 | 機身讀出的內容和韌體裡的出廠預設完全相同 |

矩陣作用在白平衡後的線性 RGB 上。每列加總為 1 時，灰色經過矩陣仍然是灰色。

## 寫入測試：哪個風格用哪一組？

1. **產生測試表。** 每一槽換成不同色相的對角增益矩陣：色相均分 360°，飽和度 0.6。工具是 `table.py testplan --round 1`。
2. **寫入、讀回、存檔。** 用 updater shell 的 `bk w`、`bk r`、`bk s`，流程見 [06](06-write-and-restore.md)。
3. **拍照。** 讓相機對著白色畫面，每個創意風格和 PP1 到 PP7 各拍一張。
4. **換一輪再拍。** 第二輪把色相打亂成 `(i*5) mod 17`，讓相鄰的槽色相相差約 106°，避免第一輪裡相鄰的槽互相混淆。工具是 `table.py testplan --round 2`。
5. **判斷對應。** 量測每張照片中央的色相，找出能同時解釋兩輪結果的槽。工具是 `nativelooks/slotmap.py`。

## 結論

- **原生處理流程確實讀這張表。** 每個有色彩的風格和 PP 都出現了對應的偏色。
- **寫入方式可行。** 寫入、讀回、存檔、重開機後仍然生效，還原也能完全回到原廠內容。
- **共用一組的模式會一起變。** 「標準」「夜景」「棕褐色」和 PP2 共用第 0 槽，改第 0 槽會同時改到這四個。
- **PP 的槽可能跟著色彩模式走。** PP 都是用出廠設定測的。PP1 和 PP3 共用第 6 槽，推測槽是跟著 PP 的「色彩模式」走的，所以改了 PP 的色彩模式，它用的槽也可能跟著變。這點還沒有驗證。
- **第 5、8、9 槽沒有對應到任何模式。** 第 8、9 槽的原廠矩陣相同，看起來像是降低飽和度的寬色域矩陣，推測可能是 S-Gamut3 或 S-Gamut3.Cine 色彩模式，但沒有測試。工具預設拒絕寫入這三槽。

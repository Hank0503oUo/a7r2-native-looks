# 06 寫入與還原

## 工具

[Sony-PMCA-RE](https://github.com/ma1co/Sony-PMCA-RE) 的 `updatershell` 會讓相機進入韌體更新模式（USB `054c:03e2`），開啟一個除錯 shell。這裡只用到其中三個指令：

| 指令 | 作用 |
|---|---|
| `bk r 0x00030001` | 讀出屬性，印出 1536 bytes 的十六進位 |
| `bk w 0x00030001 <1536 個十六進位位元組>` | 寫入屬性 |
| `bk s` | 把設定同步存回 flash |

`table.py write-cmds` 產生的指令檔依序是：讀、寫、讀回、存檔、離開，行尾為 CRLF。寫入前後各讀一次，`table.py verify` 會核對兩件事：
- 第一次讀到的，是不是你預期的舊表。
- 最後讀到的，是不是新表。

## 實際經驗

- **Windows 要用系統管理員身分。** Windows 版 `pmca-console.exe`（v0.18）要以系統管理員身分執行，才能開啟更新模式的 USB 裝置。`windows/run-updatershell.ps1` 會自動要求提升權限。按「否」時會顯示「操作被使用者取消」，相機不會有任何變化。
- **不要從 WSL 透過 usbip 操作更新模式。** 相機切到更新模式後會重新列舉，usbip 的 set-config 會逾時（-110），而相機大約 90 秒後就會離開更新模式。macOS 和 Linux 原生的 libusb 路線沒有測試過。
- **電池要夠電。** 電量低時，相機會拒絕進入更新模式，錯誤訊息是「Firmware update error: Low battery」。
- **花費時間。** 單純寫入這個屬性大約 20 秒。結束後相機會自動重開，回到一般 MTP 模式。
- **重開機後持續有效。** 寫入的表重開機後仍然有效，風格選單、JPEG 都會使用新矩陣。

## 安全措施

- **先讀出自己的原始表。** 第一件事永遠是用 `table.py read-cmds`、`extract` 讀出並保存自己相機的原始表，所有寫入都從它組合出來。專案裡不附任何 Sony 的表。
- **格式檢查。** 檢查 17 個槽是否都在預期位置，而且每列加總約 1024。至少要有 14 槽符合，否則拒絕處理，以免拿到不同機型或韌體的表時，寫錯位置。
- **只改矩陣。** `build` 只改 looks 檔列出的槽，並斷言矩陣以外的位元組完全不變。
- **預設保護與拒絕寫入的槽。**
  - 預設保護第 0 槽（標準／PP2／夜景／棕褐色）和第 10 槽（S-Log2），要改得明確取消 `--protect`。
  - 未對應的第 5、8、9 槽預設拒絕寫入。
- **還原就是把原始表寫回去。** 用同樣的流程寫回 `my_original.bin`，再用 `verify` 確認。
